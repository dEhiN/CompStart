It is clear now: CompStart is a Startup Orchestration Engine. It solves the limitation of Windows' native Startup folder by providing granular control over the state of the applications being launched (e.g., specific browser tabs, document paths, and app instances).

By allowing for the dynamic configuration of a "startup profile," you are essentially creating a tool that manages your cognitive transition into work, ensuring your digital workspace is pre-populated exactly as needed the moment you log in.

Understanding the Architecture
Based on your description, CompStart functions by:

Maintaining a Registry/Config: A central file (likely JSON or YAML) that acts as the "source of truth" for what needs to launch.

Executing Sequential Spawns: It doesn't just call binaries; it invokes specific command-line arguments (like chrome.exe "URL1" "URL2") to open the browser in a specific state.

Abstraction: It hides the complexity of Windows shell commands and URI schemes behind a simpler configuration interface that you can modify on the fly.
